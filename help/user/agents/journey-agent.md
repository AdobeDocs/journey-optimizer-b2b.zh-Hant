# B2B的歷程技能

在[!DNL CX Enterprise Coworker]聊天中，歷程技能可協助您透過自然語言設計、執行、最佳化和監視[!DNL Adobe Journey Optimizer B2B Edition]歷程。 運用這些技能，結合自動化、資料導向式建議和即時可觀察性，可減少建立和管理帳戶與人員歷程所需的時間和複雜性。

[!DNL CX Coworker]提供了一組AI技能，其中包括B2B歷程生命週期的子集。 目前可用的技能包括：

* **[歷程建立技能](#journey-creation-skills)** — 從自然語言提示建立、更新及最佳化歷程
* **[歷程可觀察性技能](#journey-observability-skills)** — 詢問關於帳戶和人員如何透過活動歷程移動的問題

按一下應用程式頂端的&#x200B;_詢問[!DNL Coworker]_ （ ![詢問[!DNL Coworker]](../assets/do-not-localize/icon-ask-coworker.svg) ）圖示以開啟[!DNL Coworker]介面。

## 歷程建立技能 {#journey-creation-skills}

歷程建立技能將您的行銷目標、參與策略和KPI轉譯為完整的B2B客戶歷程。 這些解決方案能解決B2B行銷人員現今面臨的三大挑戰：

* 處理日益複雜的客戶歷程（對象、內容和訊息以及全通路的複雜性）
* 在預算緊縮的情況下提高效率
* 瞭解應如何建構最佳客戶歷程

身為行銷人員，您可以使用這些技能來：

* **建立** — 將您的行銷目標、產品、參與策略和KPI轉換為具有自動化和條件的個人化客戶歷程
* **建議** — 運用過去的行銷參與和其他歷史資料，將歷程建立最佳化
* **最佳化** — 根據預測或實際效能分析、調整及最佳化作用中的歷程
* **管理** — 優先處理、管理及協調重疊的歷程與訊息傳送

### 基本用法

若要使用歷程建立技能，請使用自然語言，在[!DNL Coworker]提示視窗中輸入您要建立的內容：

「建立B2B歷程，邀請決策者參加最有可能開啟新管道的參與帳戶路演。」

在[!DNL CX Coworker]](./assets/coworker-chat-b2b-journey-prompt.png){width="800" zoomable="yes"}中建立B2B提示的![歷程建立技能

您提供的細節越多，回覆就越好。 如果您有描述事件或您的產品等的現有行銷資料，請貼到提示中，讓[!DNL Coworker]更能瞭解目標。

「擔任B2B歷程策略師，以建立多階段客戶帳戶歷程，在`<Solution Name>`的早期探索階段培養並吸引決策者及行銷人員參與。 目標是將匿名訪客轉換為已知連絡人、在`<domain>`.com上深化與相關內容的互動，並為`<Product Name>`銷售推廣主要合格的銷售機會。 使用電子郵件和付費媒體等管道，運用現有的受眾區段和內容。 建構4-6週期間跨意識、考量和評估階段的歷程，並為每個階段提供清晰的觸發器、操作和目標。 納入轉換率、參與分數和示範請求等KPI，並將輸出以結構化的歷程流程傳回。」

此詳細提示會提供：

* **清除意圖**：您希望AI做什麼？ 明確關於任務或結果。
* **Context-Rich**：提供相關的背景或限制。 儘可能加入範例或參照。
* **結構化格式**：使用專案符號、編號步驟或範本。
* **角色指派**：指定AI的角色 — 「擔任資料分析師……」

從簡單的提示開始，然後根據結果調整它。 使用後續提示進行迭代。

### 端對端B2B歷程建立

歷程建立技能可透過對話式體驗（而非傳統使用者介面），從自然語言文字提示和中繼資料產生端對端歷程流程（帳戶或個人歷程）。

端對端歷程提示範例：

* 建立跨管道歷程，培養過去30天未與我的內容互動的客戶。
* 建立歷程，藉由為最重要的購買群組角色提供個人化內容，將解決方案交叉銷售給意圖高且未開啟管道的客戶。
* 建立B2B歷程，邀請決策者在最有可能開啟新管道的參與帳戶中參加路演。
* 為意圖用於我的解決方案的空白帳戶建立歷程，著重於參與網站內容的人員。

### 多階段歷程

您可以充當B2B歷程設計人員，建立多階段客戶帳戶歷程，在探索階段的早期通知決策者和行銷人員。 目標是將匿名訪客轉化為已知聯絡人、深化與相關內容的互動，並努力取得銷售推廣的合格銷售機會。

* 使用管道（例如`Email`、`Paid media`、`Personalized web experiences`）來利用現有的受眾區段和內容。
* 在4-6週內跨`awareness`、`consideration`和`evaluation`階段建構歷程，並為每個階段設定明確的觸發器、動作和目標。
* 包含KPI （例如`conversion rates`、`engagement scores`和`demo requests`），並將輸出傳回為結構化的歷程流程。

## 歷程可觀察性技能 {#journey-observability-skills}

歷程可觀察性技能可讓您詢問關於帳戶和人員如何瀏覽您的B2B歷程的自然語言問題，而不需挖掘歷程地圖、記錄或儀表板。 它們涵蓋兩個主要區域：歷程進展和資料同步可觀察性。

![在[!DNL CX Coworker]](./assets/journey-observability-prompt-response.png){width="800" zoomable="yes"}中的歷程可觀察性提示和回應

### 帳戶層級歷程insight

透過提出以下問題來追蹤特定帳戶在歷程中的流動方式：

* 「給我有關Bodea Cloud帳戶的基本資訊。」
* 「告訴我客戶Northstar Services如何完成ABM Nurture Strategy歷程。」
* 「帳戶Contoso LLC何時開始此歷程？」

### 分割路徑推理和計數

瞭解採用分支的原因，以及每個路徑依循多少人或帳戶：

* 「為什麼帳戶QiDemoAccount24會前往位於分割節點c764a9的美國加州小型技術路徑？」
* 「告訴我分割節點節點459c7c中每個路徑的人數。」
* 「向我展示Account8在聖荷西路徑的人。」

歷程可觀察性技能會分析分割邏輯、帳戶屬性和活動，以說明路由決策和每個路徑的回訪計數或人員清單。

### 人員層級的歷程結果

分析帳戶內或整個歷程的個別結果，這尤其適合用於購買群組分析和追蹤決策者與影響者的行為：

* 「告訴我每個分割路徑的人數，以進行Bodea下一次網路參與歷程。」
* 「列出隱藏略過路徑中的人員。」
* 「讓我看看此帳戶在聖地亞哥位置路徑的人員。」

### 歷程生命週期和時間

擷取歷程或特定帳戶的關鍵時間戳記：

* 「此歷程何時上線？」
* 「第一個帳戶何時進入此歷程？」
* 「帳戶QiDemoAccount50何時開始此歷程？」

### 外部對象和啟用可見性

對於推送至外部管道（例如LinkedIn）的歷程，您可以檢查啟用狀態：

* 「bsmith@acme.com是否位在外部受眾中？」
* 「列出透過ObservabilityExtAudience01啟用至LinkedIn的所有人員。」

### 資料同步和管道可觀察性

歷程可觀察性技能還可以顯示資料同步健康資訊，以協助疑難排解為何帳戶或潛在客戶未包含在歷程中：

* 外部對象匯出工作量度和狀態
* 批次細分排程和完成時間
* 購買群組維護排程
* 工作管理員統計資料（已完成/失敗）
