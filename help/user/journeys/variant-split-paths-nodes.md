# 變體分割路徑

使用&#x200B;_變體分割路徑_&#x200B;節點，根據您定義的百分比配置，將帳戶或人員分配至兩個或多個歷程路徑。 如果您想要跨對象區段測試不同訊息、時間或參與策略，而不套用條件規則，此節點就十分實用。

>[!AVAILABILITY]
>
>帳戶和人員歷程的&#x200B;_變體分割路徑_&#x200B;節點可作為有限可用性功能供選取的客戶使用。 若要取得存取權，請聯絡您的Adobe代表。

## 依歷程型別比較 {#journey-type-comparison}

變體分割路徑節點會根據歷程型別使用不同的指派演演算法。 瞭解此差異對於為每種歷程型別選擇正確的使用案例非常重要。

| | 帳戶歷程 | 個人歷程 |
| - | ---------------- | --------------- |
| **演演算法** | 配額型隨機指派 | 確定性雜湊指派 |
| **決定式** | 非決定性 — 根據目前的配額狀態，相同的帳戶可能會在重新進入時指派給不同的路徑。 | 確定性 — 對於給定的已發佈歷程，總是會將同一個人指派給相同的路徑，無論他們進入或重新進入的次數如何。 |
| **A/B 測試** | 不適用 — 路徑指派在重新輸入時不穩定。 | 適合 — 一致的每人路徑指派支援受控實驗和歸因。 |
| **重新進入行為** | 帳戶每次進入歷程時可能會遵循不同的路徑。 | 人員一律依照其在第一次輸入時被指派的相同路徑進行。 |
| **發佈準確度** | 由於配額強制執行，每個路徑在一個帳戶內。 | 在1,000個或更多歷程專案時，會收斂到設定百分比的±2%以內。 |

## 與分割路徑比較 {#compare-split-paths}

_[分割路徑](./split-merge-paths-nodes.md)_&#x200B;和&#x200B;_變體分割路徑_&#x200B;都會將歷程分割成多個分支（路徑），但它們使用不同的機制：

| 外觀 | 分割路徑 | 變體分割路徑 |
| -------- | ----------- | ------------------- |
| **指派邏輯** | _條件式規則型_ — 每個實體都會根據定義的條件進行評估，並沿著其符合的第一個路徑進行。 | _以百分比為基準的指派_ — 實體會根據設定的百分比（沒有篩選條件）跨路徑分佈。 |
| **決定式** | _Deterministic_ — 只要符合相同的條件，相同的實體就會永遠遵循相同的路徑。 | _取決於歷程型別_ — 人員歷程是確定性的（同一個人一律遵循已發佈歷程的相同路徑）。 帳戶歷程不是決定性的（以配額為基礎）。 |
| **其他帳戶/人員路徑** | _支援_ — 不符合任何已定義路徑的實體可以路由至預設路徑。 | _不適用_ — 到達節點的每個實體都會指派給路徑。 |
| **使用案例** | 依已知的帳戶或個人屬性分段；依優先順序的評估。 | 分發實體以測試訊息、時間或策略。 個人歷程：適合A/B實驗。 帳戶歷程：適用於沒有每個帳戶一致性的隨機分佈。 |

## 帳戶歷程 {#account-journeys}

對於帳戶歷程，散發演演算法使用[配額型隨機指派](#account-journeys--quota-based-random-assignment)。 此演演算法是&#x200B;**_非決定性_**：每次進入或重新進入歷程時，可將相同的帳戶指派給不同的路徑。 路徑指派取決於評估時目前的配額狀態，而不是固定帳戶屬性。

### 依帳戶分割 {#split-by-account}

當帳戶到達變體分割路徑節點時，執行階段會評估在目前歷程執行個體期間已向每個路徑指派多少帳戶，並將帳戶路由到其設定配額下方最遠的路徑。

* 每個帳戶只會指派給一個路徑。
* 指派是以配額為基礎。 演演算法會動態調整分配，以接近整個母體的已設定百分比。
* 因為演演算法會追蹤配額計數，所以當總計未平均分割時，由於四捨五入，實際分配在每個路徑上最多只會偏移一個帳戶。

### 依人員分割 {#split-by-people}

在帳戶歷程中，您也可以使用變異式分割路徑節點，將帳戶&#x200B;_內的_&#x200B;個人隨機分佈到以百分比為基礎的路徑中。 如果您想要在人員層級測試不同的內容或體驗，此分割型別相當實用。 帳戶會繼續在整個歷程中移動。 依人員節點的變體分割路徑操作有以下護欄：

* 該節點的作用為&#x200B;_群組節點_，這是分割合併組合。 分割路徑會在對應的合併節點自動關閉，以便所有人員可以在不失去帳戶內容的情況下前進。
* 根據設定的百分比，帳戶中的每個人只會獲派一個路徑。
* 適用於帳戶的配額演演算法同樣適用於人員。 路徑指派不是決定性的，同一個人在重新進入時可能會遵循不同的路徑。
* 路徑中只支援人員的&#x200B;_[!UICONTROL 採取動作]_&#x200B;節點。 路徑無法進一步分割。

>[!BEGINSHADEBOX 「跨人員的分發行為」]

帳戶內的人員會以批次處理。 指派給每個路徑的號碼會計算為`floor(percentage / 100 × people_in_account)`，而&#x200B;**上次設定的路徑會接收所有剩餘的人員**。 這表示:

* 當帳戶具有奇數人數時，最後一個路徑會比先前的路徑多接收一個使用者。
* 若帳戶只有單一人員，無論設定的百分比為何，都會將該人員指派給第一個路徑。
* 若為很少人（少於10人）的帳戶，每個帳戶的分佈可能會與設定的百分比有明顯差異。 跨多個帳戶測量時，分佈會收斂於設定的比率。

>[!NOTE]
>
>此舍入行為適用於每個帳戶批次，不適用於歷程中的所有帳戶。 當帳戶大小為奇怪時，最後一個路徑系統性地接收到的人數略多於設定人數。 這是預期行為。

>[!ENDSHADEBOX]

## 個人歷程 {#person-journeys}

當人員到達變體分割路徑節點時，執行階段會根據其ID和歷程ID的雜湊將其對應到路徑。

* 每個人員只會獲派一個路徑。
* 指派是決定性的 — 對於指定的已發佈歷程，同一個人員一律會收到相同的路徑指派，無論他們進入或重新進入的次數為何。
* 雜湊只會從人員ID和歷程ID計算。 它不取決於節點位置、專案時間或任何配額狀態。 這表示重新進入歷程每次都會產生相同的路徑指派。

>[!NOTE]
>
>**人員歷程變體拆分適用於A/B測試和實驗。**
>
>由於指派是決定性的且跨重新登入一致，因此個人歷程中的變體分割路徑支援受控實驗，其中同一人必須一致地獲得相同的體驗。 使用[歷程詳細資料](./journey-details.md)檢視來監視歷程上線後跨路徑的分佈。

## 分佈演演算法

套用的發佈演演算法取決於歷程型別。

### 帳戶歷程 — 配額型隨機指派

帳戶歷程中的變體分割路徑節點使用&#x200B;**配額型隨機指派**&#x200B;演演算法。 當帳戶到達節點時，執行階段會評估在目前歷程執行個體期間已向每個路徑指派多少帳戶，並將帳戶路由到其設定配額下最遠的路徑。

配額型演演算法的&#x200B;**金鑰屬性：**

* 分佈會密切追蹤所有帳戶磁碟區的設定百分比。 由於演演算法會主動維護配額計數，因此當總計未平均分割時，由於四捨五入，實際分配只會在每個路徑漂移最多一個帳戶。

### 個人歷程 — 確定性雜湊指派

個人歷程中的變體分割路徑節點使用&#x200B;**確定性雜湊指派**&#x200B;演演算法。 當人員到達節點時，執行階段會從人員ID和歷程ID計算雜湊值，然後根據設定的百分比範圍將結果對應到路徑。 使用下列工作流程套用演演算法：

1. 執行階段會從結合人員ID和歷程ID的複合金鑰計算MurmurHash3 32位元雜湊。
1. 雜湊值會對應至10,000個大小相等的貯體範圍內的位置。
1. 值區會根據設定的路徑百分比進行分割。 例如，如果路徑為30%、30%和40%，前3,000個貯體會對應至路徑1、後3,000個對應至路徑2，其餘4,000個對應至路徑3。
1. 將人員指派至其貯體範圍包含其雜湊位置的路徑。

確定性雜湊演演算法有兩個關鍵屬性：

* **_一致性_** — 指定的歷程ID一律會將同一個人員指派給相同的貯體。 重新進入歷程每次都會產生相同的路徑指派。
* **_統計分佈_** — 當至少1,000個不重複人員進入歷程時，分佈會收斂到設定百分比的±2%以內。 如果對象較少，則每個路徑的計數與設定的比率可能會有更明顯的差異。

## 限制 {#limitations}

在歷程中使用變體分割路徑之前，請先檢閱這些限制。

### 帳戶歷程限制 {#account-journey-limitations}

>[!IMPORTANT]
>
>**路徑指派不是決定性的。**
>
>配額型演演算法無法保證相同的帳戶永遠遵循相同的路徑。 如果帳戶退出並重新進入歷程，即會根據重新進入時的配額狀態，將其指派給不同的路徑。 對於需要在歷程執行個體之間為每個帳戶指派一致路徑的使用案例，請勿使用帳戶歷程變體分割路徑。

| 限制 | 說明 |
| ---------- | ----------- |
| **不適用於受控實驗** | 因為路徑指派不是決定性的，所以帳戶歷程中的變體分割路徑是&#x200B;**不適合**，用於A/B實驗或歸因案例，這些案例需要指定帳戶一致地接受相同的處理。 |
| **小舍入偏移** | 當設定的百分比無法平均分配總帳戶數時，每個路徑最多只能有一個帳戶關閉分配。 這是預期的舍入行為，不是錯誤。 |
| **路徑指派不是等冪** | 重新進入歷程可能會為相同帳戶產生不同的路徑指派。 |
| **沒有條件式篩選** | 不同於&#x200B;_分割路徑_，變體分割路徑不套用條件。 到達節點的每個帳戶都會指派到一個路徑。 |

### 個人歷程限制 {#person-journey-limitations}

| 限制 | 說明 |
| ---------- | ----------- |
| **小尺度統計變數** | 當至少1,000個不重複人員進入歷程時，分佈會收斂到約±2%內的設定百分比。 由於專案較少，每個路徑的計數可能與設定的比率差異更明顯。 這是雜湊散佈的預期行為，不是錯誤。 |
| **沒有條件式篩選** | 不同於&#x200B;_分割路徑_，變體分割路徑不套用條件。 到達節點的每個人都會被指派到一個路徑。 |

## 新增變體分割路徑節點 {#add-variant-split-paths-node}

帳戶和人員歷程的新增和設定變體分割路徑節點的步驟相同。

1. 導覽至歷程圖。

1. 按一下路徑上的&#x200B;_新增_ ( **+** )圖示，然後選擇&#x200B;**[!UICONTROL 變體分割路徑]**。

   ![新增歷程節點 — 變體分割路徑](./assets/node-variant-split-paths-add.png){width="300" zoomable="no"}

   在歷程地圖上，節點有兩個預設路徑。

1. （_僅帳戶歷程_）在右側的節點屬性中，選擇&#x200B;**[!UICONTROL 帳戶]**&#x200B;或&#x200B;**[!UICONTROL 人員]**&#x200B;進行分割。

   如果您使用&#x200B;_[!UICONTROL 人員]_&#x200B;型別，系統會自動插入&#x200B;_關閉變數分割路徑_&#x200B;節點，以關閉群組分割。

   ![歷程畫布 — 由自動插入封閉節點的使用者分割的變體](./assets/node-variant-split-paths-people-canvas.png){width="700" zoomable="yes"}

1. 檢閱或更新每個路徑的&#x200B;**[!UICONTROL 標籤]**。

   路徑標籤會以邊緣標籤的形式出現在歷程畫布上，有助於區分Journey Analytics中的路徑。

   ![變體分割路徑節點 — 路徑名稱設定](./assets/node-variant-split-paths-names.png){width="600" zoomable="yes"}

1. 設定每個路徑的&#x200B;**[!UICONTROL 百分比]**。

   值必須是1到99的整數。

   ![變體分割路徑節點 — 路徑百分比設定](./assets/node-variant-split-paths-config.png){width="500" zoomable="yes"}

   執行總計指示器會顯示所有路徑百分比的總和。 總數必須剛好等於100%，您才能發佈歷程。 當總計不等於100%時會顯示錯誤狀態。

   ![變體分割路徑節點 — 當總計不等於100%時發生驗證錯誤](./assets/node-variant-split-paths-validation-error.png){width="500" zoomable="yes"}

   若要將百分比平均分配到所有路徑，請按一下[平均分配] **&#x200B;**。 系統會計算相等的份額並調整任何舍入，以確保總計等於100%。

1. 若要定義其他路徑，請按一下每個路徑的&#x200B;**[!UICONTROL 新增路徑]**。

   節點最多可支援20個路徑。 新增更多路徑時，請調整&#x200B;_[!UICONTROL 百分比]_，讓總數等於100%。

   您可以按一下路徑卡中的&#x200B;_刪除_ （ ![刪除圖示](../assets/do-not-localize/icon-delete-outline.svg) ）圖示來移除路徑。 只有在至少保留兩個路徑時，才能移除路徑。

   下列規則適用於變體分割路徑設定。 違規會封鎖歷程發佈。

   | 規則 | 需求 |
   | ---- | ----------- |
   | 最小路徑 | 2 |
   | 路徑數上限 | 20 |
   | 每個路徑的百分比 | 1到99的整數 |
   | 總計百分比 | 必須等於100% |
